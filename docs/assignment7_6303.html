Short Report: What a YouTube Comment Section Is a Sample Of

A YouTube comment section under 2026 U.S. midterm election coverage is neither a probability sample of the American electorate nor a representative mirror of a news channel’s viewership. Instead, it is the product of a multi-stage data-generating process shaped by platform ranking algorithms, broadcaster editorial choices, audience self-selection, and automated moderation (Freelon 2018; YouTube Data API v3 Documentation). Understanding what our quanteda keyness and sentiment models actually measure requires tracing each filter between a political event and the rows returned by tuber.

First, video discovery itself is a ranking rather than a census. Querying "US midterm election" via yt_search() for the pre-election window (1 September – 27 October 2026) and post-election window (from 4 November 2026 onward) under order = "relevance" versus order = "viewCount" yields markedly different candidate pools, even while attr(x, "total_results") reports a vastly larger universe than the 100 items returned per two-page search call. Because search.list costs 100 quota units and 1 search call per page, retrieving channel uploads directly via list_channel_videos() (playlistItems.list, costing 1 unit per 50 videos) across three distinct broadcaster types—NBC News (national broadcast network, UCeY0bbntWzzVIaj2z3QigXg), Fox News (cable news network, UCXIJgqnII2ZOINSWNOGFThA), and BBC News (international public broadcaster, UC16niRr50-MSBwiO3YDb3RA)—surfaces campaign coverage that generic keyword search misses, while exposing the trade-off of regex title filtering ("midterm|election|senate|house race|ballot"), which captures explicit horse-race headlines but drops candidate-named segments and occasionally admits non-U.S. ballot stories on international feeds.

Second, within selected videos, the gap between the comment_count reported by get_video_stats() and the comments retrieved by collect_comments() (n_max = 300) reflects four structural truncations: (1) our 300-comment collection cap, which samples the earliest or top-ranked thread pages; (2) comments held for creator review or removed by YouTube’s spam filters; (3) channel-level policy decisions to disable comment sections entirely on sensitive political broadcasts (recorded as status = "disabled" in our collection log); and (4) nested reply cascades (is_reply = TRUE). Engagement and authorship within open comment sections are heavily skewed: the top 1% of comments capture a disproportionate share of all like_count endorsements, while the top 10% most active commenters and repeated slogan or copy-pasted strings account for a substantial fraction of total volume. Consequently, unadjusted bag-of-words counts overweight vocal repeat participants.

Third, reading keywords in context (kwic()) for democrat*, republican*, trump, vote*, and ballot* prior to modeling shows that commenter invocations overwhelmingly express partisan grievances or candidate evaluations rather than neutral procedural descriptions. When we compound multi-word political phrases (house majority, senate race, early voting, mail in, election fraud, red wave, and voter id) and estimate differential keyness (textstat_keyness()), channel contrasts reflect the distinct audiences attracted to NBC News, Fox News, and BBC News rather than intrinsic differences in the election itself. Meanwhile, comparing pre-election against post-election comments captures the shift from mobilization and procedural suspicion (early voting, mail in, ballot) to outcome attribution (house majority, senate race). Validating the Lexicoder Sentiment Dictionary (data_dictionary_LSD2015) against 40 hand-coded comments further demonstrates why off-the-shelf dictionaries misread campaign discourse: competitive metaphors ("landslide", "beat", "fight"), fraud allegations ("rigged"), and pervasive sarcasm cause lexical lookup to conflate conflict framing with negative affect and ironic praise with positive sentiment.

Data Note: YouTube 2026 Midterm Collection

  • Source: YouTube Data API v3 accessed via the development version of the R package tuber (>= 2.0.0.9000) and httr2 (>= 1.1.0).
  • Permission & Compliance: Collected using a personal Google Cloud API key (YOUTUBE_KEY stored in .Renviron, excluded via .gitignore) querying public read endpoints only (skipping OAuth). Per the YouTube API Services Developer Policies (Sections III.E.4.d and III.E.6), comments retrieved via an API key constitute non-authorized data subject to a strict 30-day retention limit (delete_by recorded in manifest_pre.json and manifest_post.json), after which data/youtube/ must be deleted. No external page or transcript scrapers (yt-dlp) were used, and all commenter usernames (author_name) and channel IDs (author_channel_id) are excluded from published outputs.
  • Quota Budget: Managed under YouTube’s dual daily budgets of 10,000 quota units/day and 100 search calls/day (YouTube Quota Calculator), planned prior to execution and reconciled via yt_get_quota_usage().
  • Method:
    • Search Route: Queried term = "US midterm election" (max_results = 100, 2 pages per query) twice per period using order = "relevance" and order = "viewCount" across two windows: Pre-Election (2026-09-01T00:00:00Z to 2026-10-28T00:00:00Z) and Post-Election (2026-11-04T00:00:00Z to collection date).
    • Channel Route: Queried get_channel_details() and list_channel_videos() (playlistItems.list, 1 unit per 50 uploads) for three channels differing in kind: NBC News (UCeY0bbntWzzVIaj2z3QigXg, national broadcast network), Fox News (UCXIJgqnII2ZOINSWNOGFThA, cable news channel), and BBC News (UC16niRr50-MSBwiO3YDb3RA, international broadcaster), filtering titles with the case-insensitive regex "midterm|election|senate|house race|ballot".
    • Comment Collection: Up to 4 election videos per channel per period, capped at n_max = 300 comments (including replies) per video via collect_comments() wrapping get_all_comments().
  • Selection & Deduplication: Search results were deduplicated on video_id (distinct(video_id, .keep_all = TRUE)) prior to joining get_video_stats(), and comments were deduplicated on comment_id (distinct(comment_id, .keep_all = TRUE)) before many-to-one metadata joins (relationship = "many-to-one").
  • Known Gaps: (1) High-volume news channels upload 30–50+ clips daily, requiring 30–60+ paginated playlistItems calls (1,500–3,000+ videos) to reach 1 September 2026; (2) title regex filtering omits videos that reference only candidate surnames without explicit election keywords; (3) channels that disable comments (status = "disabled"), moderator-deleted/held comments, and threads exceeding the 300-comment cap are unobserved; and (4) YouTube rounds public subscriber_count values.

# Part 5c: Polite comment collection helper recording ok, disabled, none, or error
collect_comments <- function(video_id, n_max = 300) {
  status <- "ok"
  out <- tryCatch(
    withCallingHandlers(
      get_all_comments(video_id, max_results = n_max),
      tuber_comments_disabled = function(w) {
        status <<- "disabled"
        invokeRestart("muffleWarning")
      },
      tuber_no_comments = function(w) {
        if (status == "ok") status <<- "none"
        invokeRestart("muffleWarning")
      }
    ),
    error = function(e) e
  )
  Sys.sleep(1)
  if (inherits(out, "error")) {
    return(list(
      data = NULL,
      log  = tibble(
        video_id = video_id,
        status   = "error",
        n        = 0L,
        message  = conditionMessage(out)
      )
    ))
  }
  df_out <- as_tibble(out)
  list(
    data = df_out,
    log  = tibble(
      video_id = video_id,
      status   = status,
      n        = nrow(df_out),
      message  = NA_character_
    )
  )
}
